! Title: gtm-rr - Google Tag Manager
! Description: Notes for googletagmanager_gtm.js, which replaces uBlock
!              Origin's resource of the same name.
! Expires: 7 days
! Homepage: https://github.com/ryanbr/gtm-rr
!
! On the sites uBO's own lists already cover, this list is not needed at all.
! Installing the resource is the whole of it.

! -----------------------------------------------------------------------------
! uBO ships a resource called googletagmanager_gtm.js, and its default lists
! send both of Google's loaders to that name:
!
!   privacy.txt  ||googletagmanager.com/gtag/js$script,xhr,
!                  redirect=googletagmanager_gtm.js:5
!   privacy.txt  ||googletagmanager.com/gtm.js$script,
!                  redirect=googletagmanager_gtm.js:5,domain=~nerc.com
!
! A user resource replaces a built-in of the same name - uBO awaits its own
! loadBuiltinResources first and parses the userResourcesLocation text after it
! into the same map - so installing ours under that name is all that is needed
! for those rules to serve it. No filter below is required for that.
! -----------------------------------------------------------------------------

! -----------------------------------------------------------------------------
! Server-side tagging puts the same loaders on the site's own domain, where
! uBO's rules do not reach, and the path is what identifies them. One rule per
! site, since the subdomain is the site's choice:
!
! ||sgtm.example.com/gtm.js$script,redirect=googletagmanager_gtm.js
! ||metrics.example.com/gtag/js$script,redirect=googletagmanager_gtm.js
!
! The resource reads the container id and the data layer's name out of the
! query either way, and which loader it is standing in for out of the path.
! -----------------------------------------------------------------------------

! -----------------------------------------------------------------------------
! Where a site's CSP will not have a data: script, the redirect cannot run:
! uBO has no web-accessible URL for a user resource, so it serves one as
! data:text/javascript;base64,... and the page refuses it -
!
!   <script> source URI is not allowed in this document:
!     "https://www.googletagmanager.com/gtag/js?id=G-...&cx=c&gtm=..."
!
! The scriptlet form is injected rather than fetched, so there is no URI to
! object to. The container id still comes off the page's own script tag, which
! is in the document even though its fetch was refused.
!
! It is global rather than per site, because a CSP is not something a list can
! enumerate. Injected at document_start the page has not parsed its own tag
! yet, so the resource does nothing and watches for one: a page that never
! loads a container never gets a data layer, a registry, a ga() or a word in
! the console out of it, and a page where the redirect already ran is a no-op
! because the container id is already registered.
! -----------------------------------------------------------------------------
*##+js(googletagmanager_gtm)

! -----------------------------------------------------------------------------
! Where a site keeps page functionality inside its container, replacing the
! container cannot bring it back: googletagmanager_gtm.js answers the API and
! has no idea which tags were configured. The usual way out is to allow the
! container, which runs every other tag in it too.
!
! gtm-tag is the other way out: the tag's url goes in the filter, so only that
! one script loads. A second argument names a global the tag needs first - a
! loader asked for with &callback=fn throws if it arrives before the page has
! defined fn.
!
! Worked example, petzl.com's dealer locator, where the chain inside the
! container is OneTrust, then consent, then a Maps tag whose callback renders
! the map. Only the Maps tag is page functionality, so only it is loaded - no
! container, no consent manager, nothing else it carried. Commented because it
! carries that site's own API key, which belongs in your own filters rather
! than in a list:
!
! petzl.com##+js(gtm-tag, https://maps.googleapis.com/maps/api/js?v=3.31&key=<their-key>&callback=initGmaps, initGmaps, PageType=DealerLocator)
!
! The third argument is the container's own trigger, Key=substring against
! the page's data layer: petzl pushes PageType=DealerLocator and their Maps
! tag is held behind exactly that test. A scriptlet filter cannot be scoped to
! a path, so without it the line runs on every page of the site.
!
! A tag that needs an attribute - a consent manager carrying its tenant, say -
! gets one with attr:name=value, as many as needed, and they go on the element
! rather than the url:
!
!   example.com##+js(gtm-tag, https://host/otSDKStub.js, attr:data-domain-script=<id>)
!
! The arguments can be named in any order too: url=, needs=, when=.
!
! That second argument is a name, and a name can hold a placeholder: petzl's
! head defines an empty initGmaps so their other pages do not throw, and the
! real one is assigned inside their map controller when the page constructs
! it. So the wait is for a function with a body - answered by the empty one, a
! Maps loader draws nothing and says nothing. On that page the sign it worked
! is the browser asking for your location.
!
! Find a container's functional tags without a browser:
!
!   npm run tags -- GTM-XXXXXXX
!
! which reads the container, lists the scripts its __html tags inject, drops
! the ones that are plainly ad or analytics infrastructure, and prints a
! ready-made line for each of the rest. Most containers have none: of three
! real ones, two injected nothing but pixels.
!
! A chain counts as one tag. www.hokkaido-np.co.jp's "あなたにオススメ" slider is
! four steps deep behind the single script GTM-MZB2Z66 injects: btm.js loads
! ai_recommend.js, which waits for window.edirium_rec from
! *.rec.edirium.co.jp/scripts/recommender.js, asks b-dash for its campaigns,
! and evals the render callback they carry - and that callback is what builds
! the slides and fires aiRecommendGenerated. Naming the head of the chain
! starts all of it. Measured in Chrome against the live page: without the
! line the slider has no children, with it three.
!
! Only the tracking leg of that chain is on a list
! (||smart-bdash.com/tracking-script/ keeps bdash_log.js out, and it stays
! out), so this brings the recommendations back without b-dash's logging.
! -----------------------------------------------------------------------------
example.com##+js(gtm-tag, https://host.example/thing.js)
www.hokkaido-np.co.jp##+js(gtm-tag, https://cdn.activity.smart-bdash.com/tag-manager/bd-7verxz/btm.js)

! -----------------------------------------------------------------------------
! Where a container's job was to write into the page rather than to load
! anything, and the site has since moved that work browser-side and left the
! same code in the page inside an inert <template>.
!
! NO FILTER IS NEEDED FOR THIS. googletagmanager_gtm runs the scripts in such
! a template itself, wherever it stood in for a container, and only where the
! template holds code and no other markup, every script in it is inline, and
! none of that code creates a script, an iframe, an object or an embed or
! calls document.write - because running whatever a page holds back in a
! template would be a way to un-gate a consent-gated embed.
!
! shonenjumpplus.com is the worked example and needs nothing here: four such
! templates, one per banner area, each filling its own container and ending
! with the event the carousel waits for.
!
! A filter can name a selector where those rules are too strict - some tags a
! container injected really are third-party scripts, and that is a person
! deciding:
!
!   example.com##+js(googletagmanager_gtm, template.js-x)
!
! and a second argument names a global the template's scripts need first:
!
!   example.com##+js(googletagmanager_gtm, template.js-x, jQuery)
! -----------------------------------------------------------------------------

! -----------------------------------------------------------------------------
! Where a page waits for the global an SDK the container would have injected
! creates. The container installs someone else's script, that script defines
! a global, and the page polls for it - sometimes with no timeout anywhere in
! the wait, in which case the page never finishes loading and says nothing
! about why.
!
! b2c.voegol.com.br's sign-in screen is the worked example (uAssets #32369):
! their Amplitude tag injects the vendor's wrapper, the wrapper defines
! window.amplitude, and the login component polls for it every 1.2 seconds
! before it will redirect to the identity provider.
!
!   b2c.voegol.com.br##+js(googletagmanager_gtm, stub=amplitude)
!
! What goes up is a shape, not a vendor: a function that answers to any
! property with itself and returns undefined however it is called. undefined
! and not a plausible id, because what the page reads off it goes straight
! into a URL bound for someone else, and a resource minting a tracking id is
! not an improvement on the tracking. A global that is already there is left
! alone, and a real SDK arriving later replaces the stub.
!
! The name has to be given, because there is nothing to read it off: this
! resource is served instead of the container, so it never sees the container.
! Several names need uBO's own comma escape:
!
!   example.com##+js(googletagmanager_gtm, stub=amplitude\,amplitudeGTM)
! -----------------------------------------------------------------------------

! -----------------------------------------------------------------------------
! Where a redirect cannot land at all - an inlined bundle, or a path a rule
! cannot match - the resource has nothing to stand in front of, and the
! scriptlet form would be answering for a loader that is still running. Use
! ga-optout instead, which turns on Google's own opt-out and leaves the bundle
! to disable itself. See filters/ga.txt.
! -----------------------------------------------------------------------------
